# Risks and Validation

| Risk | Current control | Residual limitation |
|---|---|---|
| Unsafe redirect target / SSRF | Scheme, hostname, and resolved-address validation | DNS rebinding remains possible between validation and later navigation |
| Generated short-code collision or predictability | Eight-character Base62 codes use `SecureRandom`; database uniqueness and bounded insert retries enforce exactly-one-target behavior | Five consecutive collisions return `503`; code-space assumptions must be revisited at materially higher link volumes |
| Unauthenticated metadata, analytics, and deletion | Anonymous access is explicit prototype scope; soft deletion preserves analytics and after-commit cache eviction stops further redirects | Anyone who knows a short code can inspect or delete it; production requires authenticated users and server-side ownership authorization |
| Deleted or expired link served from cache | Eviction runs after the delete transaction commits; TTL is capped by remaining lifetime | Best-effort eviction relies on bounded TTL during Redis failures |
| Redis outage | Redirect reads fail open to PostgreSQL; after three failures the cache circuit opens for five seconds before allowing one recovery probe | Requests that trigger failure detection still pay up to the configured 200 ms timeout; the rate limiter deliberately fails closed, so create requests return `503` |
| Database outage | Cached redirects continue; uncached reads return `503` | Management and analytics queries require PostgreSQL |
| Analytics overload | Bounded nonblocking queue drops events instead of exhausting memory | Click totals are best-effort and may lose events on crash/overload |
| Visitor privacy | Daily HMAC of source IP; no raw IP persisted | Secret rotation and retention operations are deployment responsibilities |
| Unbounded analytics growth | Scale design specifies partitions and rollups | Archival cleanup/rollups are not implemented in this prototype |
| Dependency vulnerabilities | OWASP/NVD CVSS 7 gate passes after targeted upgrades, including Swagger UI 5.32.14 | Dependency-Check is best-effort and depends on current advisory data |

Validated locally: isolated clean-source Compose startup without generated artifacts, API lifecycle including an expired PostgreSQL row returning `410` on a cache miss, 49 Docker-backed tests with zero skips, 46 Java files formatted, static analysis, packaging, 95.8% critical-service line coverage (160/167), and a clean CVSS 7 dependency gate. A populated Flyway V1/V2-to-V3 upgrade test preserves link and click data while verifying intentional ownership-column/index removal. A 100-create/10,000-read k6 workload completed with 0% failures and 32.11 ms p95, and all 10,000 analytics events were persisted. Fault injection verified Redis-to-PostgreSQL fallback, warm-cache operation during PostgreSQL outage, and `503` on an uncached PostgreSQL outage. Read-only measurements recorded 4.88 ms warm-cache p95 and 416.99 ms Redis-unavailable p95 before the breaker. A cache-miss/PostgreSQL-path baseline measured 7.91 ms p95; after adding the breaker, sustained Redis-outage p95 measured 8.74 ms and recovered-cache p95 measured 6.85 ms, all with 0% failures. The final GitHub clone must be rechecked after push because the current validated source includes uncommitted worktree changes.
